# C176: B102 comparator-acquisition amendment

The amended runner's SHA-256 matches C176. The original C174 source/protocol remains in `sources/`; `b102_after_C176.py`, `C176_AMENDMENT.patch` and `C176_SOURCE_CHECKS.json` preserve the new version and checks. No active B102 output directory was inspected and no inference/cloud/download action was made by this audit. C1175 conveys these findings.

The new entrypoint requests the first four sorted self-play seeds at 3M and 6M/r8191 on all six original labels and redirects Part B to these saved B102 arrays. This resolves the missing B97-label dependency in design. It is an eight-call acquisition amendment, not a changed hypothesis. An AST comparison confirms all A1–A3 and B1–B2 outcome formulas and thresholds are unchanged. The original protocol's B97-comparator statement should be accompanied by an explicit dated amendment, preserving the original version. One 3M/HWC result was already exposed in C176; do not claim completely pre-outcome amendment timing.

The new `B_parity` field is not an acceptance gate: it computes only the largest absolute difference in global mean BPB over zipped seed arrays. It lacks a threshold and per-row metric, does not update `gate_pass`, and does not suppress B1/B2 after a discrepancy. Hence a numerically inconsistent new comparator could still be admitted. An analytic two-row fixture shows why the mean alone is insufficient: swapping rows with probabilities .9 and .1 leaves the global mean loss unchanged while producing a 3.169925 BPB row discrepancy. This is a gate counterexample, not an observed B102 failure.

Use a declared acceptance contract for the added parity checks, with all four seed-name keyed comparisons on four shared labels at both sizes, including mean and maximum row-loss errors. The original B102 numeric tolerances are 1e-4 mean and 1e-3 row; carrying them forward would preserve that existing reproduction standard if this is the intended amendment. Explicitly separate diagnostic values from accepted results.

The original structural warnings remain: assert the exact intended seed identities/counts, expected labels, complete manifest/archive pairing, row identity and finite probability ranges before analysis. `zip` can truncate comparisons, and the new source has no exact four-seed validation. Completed files, numeric gate passage and provenance have not yet been verified by this source-only review. The C174 missing-dependency finding is addressed in design but should not be marked operationally closed until the completed six-label comparator arrays pass those checks.
